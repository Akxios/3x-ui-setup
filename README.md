# 🚀 3x-ui setup

![Shell](https://img.shields.io/badge/Shell-Bash-4EAA25?logo=gnu-bash&logoColor=white)
![OS](https://img.shields.io/badge/OS-Ubuntu%20%7C%20Debian-blue)
![License](https://img.shields.io/badge/License-MIT-green)

`3x-ui setup` — набор Bash-скриптов для базовой подготовки собственного VPS-сервера. Проект автоматизирует установку и настройку системных компонентов, которые обычно нужны перед запуском 3x-ui/Xray: nginx, TLS-сертификат, firewall, Fail2Ban, базовые пакеты и сам 3x-ui через официальный installer.

Проект рассчитан на Debian/Ubuntu-подобные системы с `apt-get` и запускается от `root`.

---

## ⚠️ Назначение проекта и дисклеймер

Проект является техническим инструментом для автоматизации базовой настройки собственного VPS-сервера и носит ознакомительный, исследовательский и некоммерческий характер. Автор не призывает использовать проект для обхода блокировок, нарушения правил платформ или любых незаконных действий.

## Что делает проект

- Устанавливает базовые пакеты: `curl`, `wget`, `ca-certificates`, `gnupg`, `lsb-release`.
- Публикует на домене небольшой интерактивный сайт с племенем: еда, жители и сезоны.
- Может автоматически выпустить TLS-сертификат Let's Encrypt через Certbot.
- Настраивает UFW и открывает нужные TCP/UDP-порты.
- Настраивает Fail2Ban для SSH и, при необходимости, nginx botsearch.
- Устанавливает 3x-ui через официальный installer проекта [MHSanaei/3x-ui](https://github.com/MHSanaei/3x-ui).
- Автоматически настраивает панель и подписки через API 3x-ui и публикует их через HTTPS nginx.
- Показывает в конце установки закрытую карточку с адресами, портами и реквизитами доступа.
- Сохраняет итог установки и подробные логи.
- Даёт команды для статуса и управляемого удаления компонентов.

## Что проект не делает

> Безопасность SSH остаётся под вашим контролем.

- Не меняет SSH-ключи.
- Не меняет SSH-порт.
- Не отключает root-login.
- Не настраивает DNS у регистратора или провайдера.
- Не создаёт Xray-inbound и клиентов: их нужно добавить в панели для получения персональной ссылки подписки.
- Не выпускает сертификат внутри 3x-ui: сертификатом управляет nginx/Certbot.

## Требования

- Чистый или контролируемый VPS на Debian/Ubuntu.
- Root-доступ или пользователь с `sudo`.
- Python 3 для локального запуска `scripts/install.sh` (bootstrap установит его автоматически).
- Домен, A/AAAA-запись которого уже указывает на IP сервера.
- Открытый доступ к портам `80/tcp` и `443/tcp` для Certbot и nginx.
- Доступ к GitHub, репозиториям apt и Let's Encrypt.
- Резервный способ входа на сервер через панель провайдера или rescue mode.

Перед запуском проверьте текущий SSH-порт и firewall-правила. Если UFW уже используется вручную, внимательно настройте `CURRENT_SSH_PORTS`, `UFW_RESET_RULES` и дополнительные порты в `.env`.

При выпуске сертификата установщик сначала проверяет, что nginx локально отдаёт файл `/.well-known/acme-challenge/` по HTTP. Затем тот же маршрут должен быть доступен Let’s Encrypt извне на `80/tcp`. Если локальная проверка прошла, а Certbot сообщает `unauthorized` или `Invalid response`, сравните A/AAAA-записи домена с адресами VPS, проверьте внешний firewall провайдера и отсутствие стороннего прокси или HTTP-сайта перед сервером. Успешный `nginx -t` подтверждает только синтаксис конфига, не доступность маршрута извне.

## Быстрый старт

### 1) Bootstrap с меню

```bash
SHA=<полный-40-символьный-SHA-проверенного-коммита>
curl -fsSLo bootstrap.sh "https://raw.githubusercontent.com/Akxios/3x-ui-setup/${SHA}/bootstrap.sh"
# Проверьте содержимое bootstrap.sh перед запуском от root.
sudo env REPO_COMMIT="$SHA" bash bootstrap.sh
```

Bootstrap закрепит checkout за указанным SHA в `/opt/3x-ui-setup`, создаст `.env` из `.env.example`, откроет меню и предложит минимальную настройку. SHA берите со страницы проверенного коммита проекта; SHA для bootstrap-файла и `REPO_COMMIT` должен совпадать. Храните скачанный файл локально для повторного запуска.

Меню bootstrap:

```text
1) Установить / обновить сервер
2) Открыть .env
3) Удалить сервисы
4) Показать статус
5) Показать данные доступа
0) Выход
```

### 2) Установка без меню

```bash
sudo env REPO_COMMIT="$SHA" bash bootstrap.sh install
```

### 3) Локальный запуск из клона

```bash
git clone https://github.com/Akxios/3x-ui-setup.git
cd 3x-ui-setup
cp .env.example .env
nano .env
sudo bash scripts/install.sh all
```

Минимально нужно заменить:

```bash
DOMAIN="example.com"
LETSENCRYPT_EMAIL="admin@example.com"
```

Полный справочник настроек: [docs/configuration.md](docs/configuration.md).

## Как проходит установка

Команда `sudo bash scripts/install.sh all` выполняет модули в таком порядке:

1. `packages` — установка базовых apt-пакетов.
2. `firewall` — настройка UFW, SSH-портов и портов web/3x-ui/Xray.
3. `nginx` — web-root, nginx-конфиг, проверка nginx, выпуск сертификата Certbot.
4. `fail2ban` — отдельный jail `/etc/fail2ban/jail.d/3x-ui-setup.local`; существующий `jail.local` сохраняется.
5. `3x-ui` — установка закреплённой версии официальным installer без вопросов.
6. Автонастройка панели и подписок через API, маршруты nginx и проверка HTTPS.
7. `status` — краткая проверка UFW и сервисов.

Каждый модуль можно запускать отдельно:

```bash
sudo bash scripts/install.sh packages
sudo bash scripts/install.sh firewall
sudo bash scripts/install.sh nginx
sudo bash scripts/install.sh fail2ban
sudo bash scripts/install.sh 3x-ui
sudo bash scripts/install.sh status
```

## Порты по умолчанию

- `80/tcp`, `443/tcp` — web/nginx и Certbot.
- `8443/tcp` — порт, разрешённый UFW для будущего Xray inbound из `XRAY_TCP_PORTS`; сам inbound скрипт не создаёт.
- SSH-порты собираются из текущего SSH-сеанса, слушающих сокетов, `ssh.socket`/`sshd.socket` и `sshd -T`. Если определить их не удалось, установка прекращается до включения UFW.
- Панель и подписки доступны через nginx на `443/tcp`. Внутренние порты `2053` и `2096` привязаны к `127.0.0.1`.
- `XUI_PANEL_TCP_PORTS` нужен только для ручной схемы с `XUI_AUTO_CONFIGURE=false`.

Дополнительные порты задаются через:

```bash
EXTRA_TCP_PORTS="1234 5678"
EXTRA_UDP_PORTS="1234"
```

## Автоматическая панель и подписки

По умолчанию `XUI_AUTO_CONFIGURE=true`. Скрипт генерирует логин, пароль и случайный путь панели, сохраняет их **до установки**, включает подписки и настраивает HTTPS через nginx. Закреплена версия `v3.8.5`; SHA-256 установочного скрипта проверяется перед запуском. Установленная панель автоматически не обновляется.

После заполнения `.env` запуск без вопросов:

```bash
sudo bash scripts/install.sh all
```

Для bootstrap с уже заполненным `/opt/3x-ui-setup/.env`:

```bash
sudo env ASSUME_YES=true bash bootstrap.sh install
```

После успешной проверки в конце установки выводится карточка с адресами сайта и панели, логином, паролем, шаблоном ссылки подписки и портами. Публичный адрес у всех трёх сервисов использует HTTPS на `443/tcp`; `2053` и `2096` — только локальные порты панели и подписки на сервере. Локальные порты можно изменить через `XUI_PANEL_PORT` и `XUI_SUB_PORT`. Повторно посмотреть карточку можно без установки и без доступа к сети:

```bash
sudo bash scripts/install.sh access
sudo cat /root/3x-ui-access.txt
```

Реквизиты хранятся в `/etc/3x-ui-setup/access.json`, карточка — в `/root/3x-ui-access.txt`; оба файла имеют права `600`. Повторный запуск сохраняет пароль и путь. Команда `access` читает сохранённое состояние и при незавершённой проверке прямо сообщает об этом; файл карточки создаётся только после успешной проверки. После ручной смены пароля обновите `XUI_USERNAME`/`XUI_PASSWORD` в `.env`: сохранённая карточка не узнаёт о смене автоматически. Не публикуйте эти файлы и transcript installer.

Существующая панель: скрипт использует сохранённые реквизиты или `/etc/x-ui/install-result.env`, если они доступны. Иначе укажите текущие `XUI_USERNAME` и `XUI_PASSWORD` в `.env` с правами `600`. Перед изменениями скрипт проверит вход. При неверном пароле, включённой 2FA или несовместимом API настройка остановится без сброса пароля. Существующий HTTPS endpoint должен иметь доверенный сертификат. Автонастройка переносит панель и подписки за nginx; ранее выданные прямые URL могут потребовать обновления. Перед официальным installer UFW закрывает прямой доступ к локальным портам панели и подписки, в том числе при старых разрешающих правилах.

Подписка настраивается по адресу `https://DOMAIN/sub/<ID-клиента>`. Это шаблон: готовая персональная ссылка появляется после создания inbound и клиента в панели. Новые порты inbound автоматически из панели не синхронизируются с UFW — добавляйте их в `XRAY_TCP_PORTS`/`XRAY_UDP_PORTS` и запускайте модуль `firewall`.

Панель и сайт используют один HTTPS-домен. Если позже разместить на сайте сторонние скрипты или приложение, уязвимость такого сайта может затронуть панель из-за общего веб-адреса. Для активного сайта с пользовательским контентом выделите панели отдельный домен.

Проверки подтверждают вход в панель, применение настроек, локальный HTTPS через nginx и ответ сервиса подписок. Доступность через внешний firewall провайдера и содержимое клиентской подписки без созданного клиента не проверяются. При ошибке итог не помечается успешным, предыдущий файл карточки может остаться на диске; актуальное состояние попытки показывает команда `access`. Для завершения устраните причину и повторите запуск.

Для автоматического режима обязательны `ENABLE_UFW=true` и `UFW_DEFAULT_INCOMING=deny`. Даже отдельный запуск модуля `3x-ui` сначала настраивает UFW. Если на сервере есть глобальный IPv6, UFW должен иметь `IPV6=yes` в `/etc/default/ufw`. Если порт панели, подписки, nginx или Xray занят другим сервисом, установка останавливается до изменения firewall. Порты `EXTRA_*` явно предназначены для ваших других сервисов.

Чтобы оставить настройку панели ручной, задайте `XUI_AUTO_CONFIGURE=false`. Этот флаг не отменяет уже применённую настройку. Отдельный запуск модуля `3x-ui` с автонастройкой требует уже выпущенного сертификата nginx.

## Сайт с племенем

На главной странице показывается домен и простая игра: племя начинает со 30 мужчин, 40 женщин и 90 единиц еды в 100 году до н. э. Можно собирать еду, кормить жителей, переходить к следующему сезону и создать новое племя. Состояние игры сохраняется только в `localStorage` браузера; скрипт страницы не отправляет игровые данные на сервер. Если хранилище браузера недоступно, игра работает без сохранения прогресса. Обычные журналы запросов nginx при этом остаются системными журналами сервера.

Повторный запуск модуля `nginx` обновляет только страницу, помеченную как созданная проектом, или прежнюю заглушку, точно совпадающую с исходным шаблоном. Собственный `WEB_ROOT/index.html` скрипт не перезаписывает. Чтобы применить новый шаблон к существующей установке, выполните `sudo bash scripts/install.sh nginx`; обновление страницы также произойдёт при полном повторном запуске установки.

## Сертификаты и 3x-ui

Nginx выпускает сертификат через Certbot. Не выпускайте второй сертификат внутри 3x-ui для того же домена без необходимости.

Для Xray-inbound, которому требуется TLS, можно использовать существующие пути (HTTPS самой панели обслуживает nginx):

```bash
/etc/letsencrypt/live/example.com/fullchain.pem
/etc/letsencrypt/live/example.com/privkey.pem
```

Если у вас уже есть сертификат, отключите автоматический выпуск и укажите пути вручную:

```bash
NGINX_AUTO_HTTPS="false"
NGINX_USE_HTTPS="true"
NGINX_CERT_PATH="/path/to/fullchain.pem"
NGINX_CERT_KEY_PATH="/path/to/privkey.pem"
```

## Логи и итог установки

По умолчанию:

- итог установки сохраняется в `/root/vps-bootstrap-summary.txt`;
- подробные логи сохраняются в `/var/log/vps-bootstrap/`;
- transcript официального installer 3x-ui сохраняется отдельным файлом в `LOG_DIR`;
- команды `status` и `remove` пишут временные summary в `LOG_DIR`, чтобы не перезаписать итог установки.

При `VERBOSE=false` установщик показывает только ключевые шаги и последние строки лога при ошибке. При `VERBOSE=true` вывод apt, ufw, systemctl, nginx и certbot будет подробным. Вывод официального installer 3x-ui в автоматическом режиме остаётся в отдельном закрытом transcript независимо от `VERBOSE`.

## Обновление существующего сервера

Скрипт автоматически управляет только nginx-конфигом с первой строкой `# Managed by 3x-ui-setup`. Старый конфиг проекта без этой строки и чужой конфиг он не перезапишет. Если вы проверили, что `/etc/nginx/sites-available/DOMAIN` действительно создан прежней версией этого проекта, добавьте эту строку первой в файл и повторите установку; скрипт затем сохранит резервную копию и проверит `nginx -t`. Для стороннего сайта используйте отдельный домен/виртуальный хост, чтобы его настройки не были затронуты.

Перед повторной установкой сертификат остаётся обслуживаться по HTTPS. Временный HTTP-конфиг нужен только при первом выпуске сертификата; при ошибке Certbot исходный конфиг восстанавливается. Fail2Ban настраивается через собственный jail-файл. Старый `jail.local` с отметкой прежней версии проекта переносится автоматически; пользовательский файл сохраняется.

Для установки из проверенной версии проекта скачивайте `bootstrap.sh` по SHA коммита и передавайте тот же SHA как `REPO_COMMIT`. Bootstrap получает коммиты и переключается на указанный SHA до запуска кода из checkout; обновления ветки `main` не меняют закреплённую версию. Запуск файла из `main` остаётся незакреплённым на первом этапе. Для другой версии официального 3x-ui задайте вместе `THREE_X_UI_VERSION`, `THREE_X_UI_INSTALL_URL` и `THREE_X_UI_INSTALL_SHA256`. Без совпадения SHA-256 скачанный installer не запускается.

## Удаление

Интерактивное удаление через bootstrap:

```bash
sudo env REPO_COMMIT="$SHA" bash bootstrap.sh remove
```

Локально после установки:

```bash
sudo bash scripts/install.sh remove
sudo bash scripts/install.sh remove nginx
sudo bash scripts/install.sh remove fail2ban
sudo bash scripts/install.sh remove 3x-ui
sudo bash scripts/install.sh remove ufw
sudo bash scripts/install.sh remove all
```

По умолчанию удаляются управляемые конфиги/сервисы, но web-root, certbot-сертификаты, данные 3x-ui и apt-пакеты сохраняются. Общий `/etc/fail2ban/jail.local` не удаляется.

Для более жёсткого удаления включите нужные флаги в `.env`:

```bash
REMOVE_WEB_ROOT="true"
REMOVE_CERTBOT_CERT="true"
REMOVE_XUI_DATA="true"
PURGE_PACKAGES="true"
```

`REMOVE_CONFIRM=true` отключает интерактивные подтверждения. Используйте этот флаг только когда точно понимаете последствия.

## Диагностика

Проверить краткий статус:

```bash
sudo bash scripts/install.sh status
```

Для подробного вывода установите `VERBOSE="true"` в `.env` перед запуском `status`. Реквизиты повторно показывает `sudo bash scripts/install.sh access`.

Типовые места для проверки:

- `/root/vps-bootstrap-summary.txt` — итог установки, домен, лог, путь к сохранённым реквизитам.
- `/var/log/vps-bootstrap/` — подробные логи команд.
- `systemctl status nginx --no-pager -l` — состояние nginx.
- `nginx -t` — проверка nginx-конфига.
- `ufw status verbose` — firewall-правила.
- `fail2ban-client status` — состояние Fail2Ban.
- `systemctl status x-ui --no-pager -l` — состояние 3x-ui.
